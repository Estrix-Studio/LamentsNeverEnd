# LoopShift

A 2D cardinal room streamer with fixed connections, seeded weighted pools, bounded instance pooling and a visual graph editor.

## Install and run the sample

For UPM, choose **Window > Package Manager > Install package from tarball** and select the supplied .tgz. Import **Minimal Top Down** from the package's Samples section. For the .unitypackage distribution, import all included files. Open **MinimalTopDown.unity** in the imported sample folder and press Play.

Move with WASD/arrow keys or hold the on-screen direction buttons. Enable Auto-walk east to observe repeated physics-triggered transitions. Restart resets the seeded run. Atrium's east exit has a fixed bidirectional route to Gallery; other exits use the weighted Endless pool. The sample includes its own original geometric art and unlit shader, and requires no input, UI, art, or rendering package.

## Author a level

1. Create a prefab with a LevelZone component at its root. Give each room a stable ID.
2. Add child objects with LevelExit and a trigger Collider2D. Set a cardinal direction and an exit tag. Opposing exit anchors meet at the shared doorway.
3. Refresh exits in the LevelZone inspector and configure bounds. Save the prefab before adding it to a graph.
4. Open **Window > LoopShift > Level Graph**, choose New, and drag your saved room prefabs onto the canvas.
5. Connect opposing exit ports. Right-click a room to set the start room or add it to a pool. Use the details panel to edit weights and global pool rules.
6. Add EndlessLevelRunner to the scene, assign the graph, and register your player Transform in Targets. The actor needs a Collider2D and an appropriate Rigidbody2D for trigger events.
7. Resolve graph errors before Play. Pool rules apply to every matching exit; fixed routes take priority.

Canvas: drag nodes to move, middle-drag to pan, wheel to zoom, F to frame all. Delete removes a selection. Undo/Redo restores authoring changes. Use the rename field to keep graph references consistent.

## Runtime contracts

Graph configuration is compiled at the start of a run. Stop and restart after changing routes. ActiveZones is a live read-only view. ZoneSpawned, ZoneEntered, ZoneBecameCenter and ZoneDespawned expose room lifecycle; implement ILevelZoneLifecycle on room behaviours to reset reusable state. Disabling/destroying the runner releases rooms and restores registered actors' original parents.

Preload radius is clamped to active radius. Start with radius 1; room count grows with the area of the square neighborhood. maxPoolInstancesPerPrefab and maxPooledInstances bound retained instances. A zero preload radius creates the next room on demand. Pool callbacks and user code may allocate even when warmed routing/streaming operations do not.

Connect compatible opposing anchors and consistent room dimensions for a coherent geometric layout. When preloading is enabled, the current room's immediate routes replace conflicting or misaligned neighboring cells before the player approaches. More distant speculative paths retain occupied cells. Accepted crossings also resolve conflicts. This is a 2D cardinal grid system, not a freeform 3D world generator.

## Compatibility and verification

Development package imports, automated tests, Windows player builds and player execution have passed in Unity 2022.3.62f3 and Unity 6000.3.25f1 LTS. Built-in and URP 17.7.0 sample camera renders have also passed in Unity 6000.7.0b1. Release qualification, visual editor inspection and final store preparation remain in progress; this repository build is not yet an Asset Store release. The included sample shader supports Built-in and URP; it does not provide an HDRP sample material.

Runtime depends on Unity's 2D physics module; editor/sample controls use IMGUI. The runtime does not reference the host game's scripts or third-party packages. Tests use Unity Test Framework and are optional for consumers.

The authoring, integration/migration, tuning/troubleshooting guides and lifecycle contracts ship under Documentation~ in UPM and Documentation in the .unitypackage distribution. Runtime/editor source is included in both distributions.
